# Анализ архитектуры Needle 2 для поддержки русского языка

## Обзор
В целом, кодовая база Needle 2 хорошо подготовлена для работы с различными языками:
- В большинстве мест используется кодировка UTF-8 (принудительно).
- Аргументы `json.dumps()` в `finetune.py` и `_worker.py` уже содержат флаг `ensure_ascii=False`.
- Regex в `needle/agent/tools.py` (`r"\s+(\w+)\s*(?:\([^)]*\))?\s*:\s*(.+)"`) использует `\w+`, который в Python 3 по умолчанию охватывает символы Unicode (и кириллицу в том числе), поэтому парсинг аргументов из docstring работает.

## Узкие места для кириллицы (Bottlenecks)
1. **Токенизация**: Модель ограничена окном контекста в 256 токенов (`kv_window`). Так как кириллица зачастую токенизируется менее эффективно (часто 1 токен = 1-2 символа или байты, fallback к BPE байтам), это может привести к слишком быстрому заполнению окна, обрезая важную информацию для русскоязычных задач.
2. **Оценка метрик (Inference/Metrics)**: В текущих тестах (`tests/test_grounding.py`, `tests/test_environments.py`) часто используется проверка на точное совпадение (exact match). Русский язык обладает богатой морфологией (падежи, склонения), что приведет к ложным падениям тестов (например, "кухня" и "кухне"). Потребуется внедрение fuzzy-matching или базовой лемматизации.
3. **Генератор данных (`finetune.py` и `cli.py`)**: Промпты для синтеза данных к LLM жестко заданы для англоязычного контекста. Необходимо предусмотреть флаг языка или шаблоны промптов на русском для генерации правильного контекста.
4. **Конфигурация Regex**: В `.github/workflows/publish-component.yaml` и `doc/apis.md` есть упоминания `-regexp`. Хотя это не блокирует кириллицу, нужно быть внимательными при добавлении новых правил валидации ответов (например, в byte-level grammar `needle.model.decode`). Byte-level грамматика должна уметь корректно мапить UTF-8 последовательности байтов на валидные кириллические символы.
